# 规格文档：幕山 Moshine 品牌重塑 + 闭源商用化一期改造

> 产物所属 Spec 目录：`.trae/specs/mosliy-brand-relaunch/`
> 自然语言：中文
> 关联仓库：用户 fork 的「影策」开源项目（域名 mosliy.com 已购），改造后不再开源。
> 品牌定位：极致黑白极简 · 高端创作工业感（Linear / Notion 路线）。

***

## 0. 背景摘要（问题、用户、目标、非目标）

### 0.1 问题

当前仓库名为「影策 open-ai-canvas」，作为 MIT 开源项目对外分发：

* 品牌名（影策）、产品名（open-ai-canvas）、代码内文案、导航命名、视觉标识都是"开源开发者视角"，缺少面向终端付费用户的 SaaS 品牌心智；

* 导航、入口页、定价、增长、合规、支付、私域等商用化要素要么缺失，要么以内部/开源形态存在；

* 内部规则文件 `AGENTS.md` 是面向协作者公开的开发约定，不应继续作为闭源版本的公开文件；

* 缺少对 WowTV / NeoDomain 成熟 SaaS 模式的借鉴落地（向导式入口、作品展示墙、邀请码准入、赛事体系、四产品矩阵导航、原子能力矩阵、真人转绘、主角模式卖点、导出专业软件衔接、飞书私域、双端 UI、定价分层），和 DramaClaw 的垂直护城河（草稿草图锁定 + 360°导演世界 V1 + 资产 Prompt 中间件）。

### 0.2 目标用户与典型角色

| 角色               | 期望                                                 |
| ---------------- | -------------------------------------------------- |
| C 端个人创作者         | 零门槛一句话进入，能快速做出能发布到抖音/小红书/视频号的 1–3 分钟短剧或风格转绘        |
| B 端中小工作室（3–20 人） | 多人协作 + 共享资产库 + 角色一致性锁定 + 可导出工程文件回 PR/AE/DaVinci 精修 |
| 品牌方 / MCN / 企业客户 | 私有化部署 + 可白标 + 专属模型渠道 + SLA + 商单对接                  |
| 运营管理员            | 邀请码发放、赛事/活动发布、创作者成长计划分层、积分消耗策略热更新、内容审核处理、财务对账      |

### 0.3 目标（Goal）

**一期（Phase-1）上线目标：把 fork 后的"影策"改造成品牌为「幕山 Moshine」、域名 mosliy.com、具备完整商用化"外表面"和增长/收费/合规骨架的闭源 SaaS 产品，做到"可以立刻邀请第一批 500 种子用户进入并收第一笔真金白银"。一期覆盖全部 17 个实施任务（详见 tasks.md），不延期任何一项。**

> 注：垂直硬核能力（DramaClaw 类的草稿草图锁定、360°导演世界、资产 Prompt 中间件）作为 Phase-2 后续迭代，不纳入本 spec 交付范围；但本 spec 必须为它们预留 UI 入口和卖点占位（例如"主角模式即将上线"徽章）。

### 0.4 非目标（Non-Goal）

* 不做即梦级别复杂的模型接入改造；现有 Provider 层（即梦/Seedance/OpenAI 兼容/Gemini Veo/Novita）保持原样；

* 不在一期接入真实微信/支付宝/苹果内购 SDK 的线上收款，只做前端收款 UI 骨架 + 后端服务接口占位（`POST /api/payment/wx/prepay` 等），保持与现有 `CreditLedger` / `RuntimePolicy` / `Wallet` 的合同兼容；

* 不开发 H5 手机端的全部功能，只做 PC 创建台 + 作品 Showcase + 钱包/邀请/任务中心的移动响应式骨架；

* 不在一期真正实现"飞书机器人自动签到送积分"，只在 UI 显式暴露"签到领积分"入口和规则说明，后台人工/脚本一期人工处理；

* 不删除任何现有开源 MIT 版权注释（GPL-传染性风险不存在，但要保留原始作者署名，以符合 MIT 协议第 2 条的版权声明义务）。

* 一期不修改 Canvas Agent（`canvas-agent/`）、Codex 插件（`plugins/infinite-canvas/`）、部署脚本（`scripts/`）、docker-compose 里的镜像名"open-ai-canvas"；这些**允许继续沿用旧代码名**，仅在对终端用户可见的品牌表面（HTML title、导航、登录页、页脚、邮箱签名、管理后台品牌位）替换为幕山 Moshine。

## 1. 品牌系统（幕山 Moshine 完整品牌定义）

### 1.1 品牌基础信息

* **主品牌名（中文 + 英文）**：幕山（中文主品牌名）· Moshine（英文主品牌名）。中文「幕」取银幕/分幕之意，「山」取稳定·专业·高度·可攀登。英文 Moshine = Mosliy 首 Mo + Shine（光，胶片感光），谐音 Machine 暗示创作机器。

* **域名**：`mosliy.com`（主站，已购）；域名与品牌名不完全相同属正常（品牌叫幕山，域名 mosliy.com 作为国际入口）。后台建议区分：`app.mosliy.com`（用户控制台）、`admin.mosliy.com`（运营后台一期可和用户后台同域，放在 `/admin` 路由内）。品牌官网可考虑一期使用 `mosliy.com` 直接作为 SaaS 入口。

* **Slogan（英文 + 中文两句）**：

  * 中文主 Slogan：`幕山 · 每一帧，都值得立一座山。`

  * 英文主 Slogan：`Moshine — Every frame, a mountain.`

  * 欢迎引导句（向导式首页 greeting）：根据时间段动态切换：`早上好 / 下午好 / 晚上好，今天要为哪个故事立一座山？` + 输入框提示：`粘贴小说或创意，幕山陪你一帧一帧搭建…`

* **品牌个性（Brand Voice）**：极致黑白极简 · 高端创作工业感。不极客、不堆砌术语、不喊"最强/顶级"，走"克制、专业、有野心的创作攀登者"路线——

  * 按钮文案用行动动词（"立即投拍"、"继续上一个项目"、"邀请朋友开拍"），不用技术术语（不要"一键执行画布子图生成任务"）。

  * 空态用电影/登山场景式比喻（不是"暂无数据"而是"剧本还未落笔，先从一个创意开始吧 🎬"；不是"暂无项目"而是"山脚已就位，向上开拍吧"）。

  * 核心隐喻：每一帧画面都是一座值得攀登的山，每一部片子都是一座山岭。

### 1.2 品牌色（极致黑白极简 · 高端工业感）

沿用现有三层 design token（`web/src/styles/globals.css` 的 primitive 不变），只**在 Semantic 层引入幕山专属语义色**。整体走 Linear / Notion 路线——纯黑白灰为主，仅一处极淡的品牌强调色点缀：

* **品牌主色（Primary / Brand）**：幕山黑 —— 极致深黑，对应现有 primitive oklch 调色板中 neutral / zinc 的 950 档（`--brand` = `var(--neutral-950)` 或最深的 `--ink` token，作为主文字色、顶栏背景选中态、主 CTA 按钮文字色）。

* **品牌强调色（Accent）**：幕山微光 —— 一处极淡的冷灰金（primitive amber 200-300 档的极低饱和度，`--accent` = `var(--amber-250)` 或类似；用于关键 CTA 按钮背景、选中徽章高光、积分/金币图标）。**色彩饱和度必须 ≤ 15%**，确保整体仍呈现黑白灰质感。

* **品牌对比色（Brand Contrast）**：纯白 `--brand-contrast` = `var(--neutral-0)` 或 `#fff`，用于深色背景上的文字。

* **品牌柔色（Brand Soft）**：`--brand-soft` = `var(--neutral-50)`，用于卡片表面、选中态淡背景。

* **品牌微光（Brand Glow）**：`--brand-glow` = `var(--neutral-100)`，用于 hover 微光、描边淡阴影。

* **不使用品牌渐变**。幕山的视觉核心是「黑白对比 + 排版张力」，不依赖渐变。Logo、Hero 区、按钮均用纯色（黑/白/灰）+ 字重对比表达层次。

* **要求不引入新的 primitive 颜色字面值**，只允许在 Semantic 层引用已存在 primitive；违反此项即为**不满足验收标准**。

* **暗色主题**：主色翻转为纯白底色 + 深灰文字（`--brand` 在 dark mode = `var(--neutral-50)`），强调色微光保持一致。

### 1.3 品牌 Logo（一期可用 CSS 字标 + 图标占位）

* **形式一：字标（Wordmark）**：中文「幕山」两字作主字标，用 `--font-sans`（项目现有 sans-serif），**纯黑色、不加渐变**、字重 700-800、字间距微收；PC 顶栏宽度 ≥ 1280 时展示完整字标「幕山」+ 英文小字副标「Moshine」+ 一句微小副标「每一帧，都值得立一座山」。宽度 < 1280 时只显示「幕山」两字。

* **形式二：图形 Mark（Logo Icon）**：一个 44×44 px 的纯黑（或纯白在暗色主题）圆角 14 方块，内部用 CSS `::before` + `::after` 画一个负形"幕布齿孔 + 三竖山峰"（幕 = 银幕齿孔，山 = 三竖结构，双重隐喻）。**不使用渐变或彩色填充**。宽度 < 1280 时顶栏只显示图形 Mark，hover tooltip 显示「幕山 Moshine」。

* **Favicon / PWA Logo**：图形 Mark 导出为 SVG（黑白单色），同时生成 16/32/64/180 PNG（一期允许**在 HTML** **`<head>`** **`<link rel="icon">`** **使用内联 SVG data URI 占位**，不强制生成 PNG 文件；但必须把"open-ai-canvas / 影策"字样的旧 favicon 完全替换掉）。

将当前"创作台/画布/项目/任务/素材/技能/钱包/设置"8 项主导航，重组为用户心智清晰的 **4 产品 + 3 个人中心** 分组：

## 3. 商用化灵感 Phase-1 的功能需求（WowTV 12 灵感落地拆分）

### 3.1 幕山投拍：向导式创作入口（灵感 #1）

* **URL**：`/flow`（登录后的默认 landing page，替代现在的 `/create`）；未登录时跳 `/login` 并保留重定向 state。

* **四个 Tab**（对应四种创作路径），每个 Tab 一张独立卡片：

  1. **🎬 一句话投拍**：文本输入框（高度 ≥ 140px），placeholder「粘贴一段小说原文 / 写一句话创意，例如『穿越到北宋的程序员用现代代码拯救汴京瘟疫』……」；下方三个快捷 chips「都市爽文」「古风言情」「赛博朋克悬疑」。提交后 → 后端调用现有剧本拆解 skill → 自动创建 Project → 跳到 `projects/:id/chapters`。
  2. **🖼 图片创作**：选择模型（下拉）+ 画幅比例 chips（1:1 / 3:4 / 9:16 / 16:9 / 4:3 / 21:9）+ prompt 输入 → 批量生成 N 张。提交流程复用现有图片生成通道。
  3. **🎞 视频投拍**：文生视频 / 首尾帧 / 多图参考三个子 Tab。
  4. **📚 从模板投拍**：占位卡片网格，共 6 张。分别是「都市爽剧·百集连载模板」「古风言情·30 集模板」「电商种草·竖屏广告模板」「乙游视觉小说模板」「博物馆文物复活模板」「品牌 IP 故事短片模板」。每张卡片点击后 → clone 模板项目结构（项目、章节、空角色位、空分镜表头）。模板项目数据一期为前端 mock 硬编码数据结构，二期接模板市场后端。

* 右侧边栏显示「我的最近 5 个项目」+「继续上一个未完成项目」快速入口。

### 3.2 幕山首映：作品展示墙 + 查看创作过程（灵感 #2）

* **URL**：`/stage`，公开页，无需登录。

* **筛选器顶栏**：分类 chips（全部 / 都市 / 古风 / 悬疑 / 电商广告 / 视觉小说 / 真人转绘）+ 时长 chips（<30s / 30s-3min / >3min）+ 排序（最新 / 最热）。

* **卡片网格**：每个作品一张 16:9 封面图卡片 + 作品标题 + 作者（「幕山创作者 · 小剧场导演」昵称占位 + 头像）+ 徽章（如「#1 本周爆款」「主角模式 Pro」）。

* **卡片右下按钮**：两个主按钮「▶ 播放成片」（弹窗内播放视频）+「📖 查看创作过程」。

* **创作过程弹窗**：按"剧本 → 角色资产 → 分镜草稿 → 精渲成片 → 剪辑合成"时间线展示，每一步有缩略图+说明，底部固定「🎬 用此模板投拍」按钮（登录→clone 模板→进入投拍）。

* 数据来源：一期作品卡片数据 10 条为 `web/src/stages/mock-showcase.ts` 前端 mock（占位高清封面 + 视频可使用第三方 demo 视频占位）；后端接口契约先定义 `GET /api/showcase?category=&sort=&page=` 但不真正连数据库，二期再接。

### 3.3 幕山攀登计划：邀请码准入 + 邀请裂变送积分（灵感 #3）

* **注册流程改造**：`/register` 增加必填字段「邀请码」。后端新接口 `GET /api/invite/:code/validate` 校验邀请码存在、未过期、未超配额。若系统设置 `CANVAS_PUBLIC_REGISTRATION=true` 则邀请码可为空（兼容现在的公共注册开关）。

* **邀请好友页（`/creator/invite`）**：

  * 展示用户自己的邀请链接 `https://mosliy.com/?invite=XXXXXX` + 二维码 SVG + 「复制链接」「保存二维码」按钮。

  * 展示「奖励规则」：

    * 好友通过你的邀请链接完成注册 → 你 +100 积分，好友 +200 积分（一次性）

    * 好友首次完成任意充值（金额 ≥ 50 元）→ 你额外返充值金额的 20% 等值积分，永久生效一次

    * Pro 会员每月可生成 10 个邀请码；免费用户 2 个；Studio 50 个

  * 已邀请列表（头像/昵称/注册时间/状态/是否充值/奖励积分）

* **后端模型新增**（一期定义结构 + 空 service 方法，不真的强制建表迁移成功就验收通过）：

  * `InviteCode { id, code, createdBy, quotaUsed, quotaTotal, createdAt, expiresAt }`

  * `ReferralReward { id, referrerId, refereeId, rewardType, credits, status, relatedOrderId, createdAt }`

* 现有 `Announcement` 后台 + `admin/credit-operations` 页面扩展「手动批量生成邀请码」入口（一期先加 UI 入口 + 空接口占位）。

### 3.4 幕山攀登计划：赛事/活动系统骨架（灵感 #4）

* **URL**：`/creator/activities`，列表页 + 详情页。

* 列表卡片：活动封面图 + 标题 + 时间标签（进行中/已结束/即将开始）+ 报名费标签（免费 / ¥XX）+「立即报名」按钮。

* **详情页（`/creator/activities/:id`）**：

  * Banner 区：主标题 + 副标题 + 奖金池金额高亮（¥XX 总奖池 / XX 万积分）

  * 赛制介绍（赛事时间：报名→征集→初评→复评→颁奖；投稿要求：时长/比例/分辨率/原创/品牌植入；奖品：金奖/银奖/铜奖/拉新奖/社媒人气奖）

  * 创作支持：报名成功→激活奖励→发布奖励→爆款奖励→宣推奖励阶梯列表

  * 「我要报名」按钮（登录后显示；点击→弹出表单：姓名/昵称/联系方式/作品赛道→提交→返回参赛资格激活）

* **管理后台（`/admin/activities`）**：一期新增菜单入口 + CRUD 骨架表单（标题/封面/时间/奖金池/规则说明/是否置顶），对应 `Activity` 模型 + service 空方法。

* 一期活动数据：预设 1 条 mock 活动，标题为「第一期幕山投拍挑战赛 · 为故事立一座山」，总奖池 10,000 元，报名全程免费。

## 8. 验收范围之外

* Canvas Agent（`canvas-agent/`）、插件（`plugins/`）、部署脚本（`scripts/*.sh`）、docker-compose 内部服务名/镜像名的重命名不在一期。

* 对接真正的微信/支付宝 SDK、第三方内容审核 SDK、飞书机器人签到 SDK 不在一期。

* 草稿草图锁定、360° 导演世界、资产 Prompt 中间件三项功能（Phase-2 护城河）不在一期范围，仅要求有对应 UI 入口和 Beta 徽章占位。
